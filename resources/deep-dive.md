# Socratic Mentor — Deep 档

复杂主题、多个嵌套误解、或要跨多次会话时用。

## 多误解映射

诊断阶段不只找"会不会"，要画出心智模型：

- 让对方描述 / 画出几个概念之间的关系，看缺失的连接、错误的因果箭头、混乱的层级。
- 预测-观察-解释（POE）：给一个场景问"会发生什么" → 记录预测（暴露心智模型）→ 给真实结果。

记录每个误解：它为什么存在、依赖哪些前置错误。误解之间往往有依赖——先修底层的。

## 多阶梯

复杂主题不是一条线。给每个子概念单独一条阶梯，标清楚它们的依赖顺序。脚手架按子概念分别跟踪，不要用一个全局级别。

## 按回答分支

不要预先写死整条路径。每个真实回答都可能改变下一问：

- 答案显示新的误解 → 插入针对性的揭矛盾问题。
- 答案显示已经懂 → 跳过中间阶梯，直接上边界 / 迁移。

## 会话状态与恢复（仅在长会话 / 多次会话需要时）

恢复时先查看最近真实回答和获准读取的学习记录，确认目标、待验证项与下一步。旧摘要与新记录冲突时，优先采用用户当前纠正，并核实关键事实；不要因为旧摘要写着“完成”就跳过尚未作答的检查。

只在目标、误解、验证结果或下一步发生变化时更新紧凑状态，不必每轮重写：

```text
learning_goal:      [目标 + 成功标准]
preferences:        [用户已表达且本次相关的语言 / 呈现偏好]
source_context:     [相关资料版本、提交或观察日期；按需]
last_evidence:      [最近真实回答及其支持的结论]
misconceptions:     [尚未解决的问题 + 对应回答]
error_tags:         [错误类型与样本数量；按需]
current_scaffold:   [示范/引导/陪练/放手/转教]
validation_status:  [已讲 / 提示后完成 / 独立验证 / 待复习]
pending_checks:     [未作答或未通过的检查]
next_step:          [下一问或下一项练习]
```

这些状态默认留在当前会话。只有用户已要求保存、更新课程进度或适用的上层指令已授权时，才写入指定学习记录；沿用已有授权，不反复确认。只存必要信息，不把个人学习状态或内部项目资料写进公开仓库。安排复习建议不代表创建日历提醒或自动任务。

## 进度卡（按需）

恢复长课程或状态变化时，简要列出“已讲、待验证、已验证、待复习”。学习者不需要每轮看到同一张卡。

- 总单元数、截止日期和起始日期可靠时才计算百分比或时间进度；缺失时直接写“未设定”。
- 学完的单元数不等于已掌握的单元数，不能混用分母。
- 如使用进度条，放在等宽代码格式中；`=` 和空格的 20 格条可表示每格 5%，不要声称在任意字体下都能对齐。
- 不从单次错误、语法问题或提示后答对推断长期能力。

```markdown
| 范围 | 已讲 | 独立验证 | 待处理 |
|---|---:|---:|---|
| 当前模块（共 5 单元） | 3/5 | 2/5 | 第 3 单元迁移检查未作答 |

下一步：先完成第 3 单元的一个新例子，再决定是否进入第 4 单元。
```

## 可视化笔记产出（已请求或已授权时）

当用户要求学习笔记、或已建立包含笔记的课程流程时，单元结束后按既定目录和格式整理。HTML 适合自包含的表、图和交互内容；用户指定其他格式时遵从其选择。没有文件写入授权时，在会话内给简短小结即可。

笔记保留关键因果链、实际出现的误解、资料来源，以及独立掌握和待验证的区别。先让学习者完成回想，再展示包含答案的总结；不把教师写好的分析冒充学习者已经会做的结果。

HTML/SVG 写作检查：

- SVG 多行文字用多个 `<text>` 或 `<tspan>`，不在 `<text>` 中使用 `<br/>`。
- 检查 viewBox、标题和节点间距；各 SVG 在自己的 `<defs>` 中定义所需 marker。
- 自动展示预览前，用浏览器实际渲染并检查可见内容；打不开时提供文件链接并说明未完成渲染检查，不能把源码面板当预览。
- 仅在授权范围内更新进度表；把尚未完成的检查留为待验证，不自动推进到“已掌握”。

## 深度迁移验证

- 近迁移（同领域类似题）→ 修改迁移（改过的题）→ 远迁移（不同领域同结构）。
- Feynman 测试：能不能讲给小孩、同事、专家三种听众。
- 转教测试："你会怎么教别人这个？他们会卡在哪？"

## 多次会话测验节奏

主动回想与间隔练习用于检查保留和迁移，不用未经核实的固定遗忘百分比说服学习者。节奏取决于目标、时间和已有约定；下表是选项，不是强制的完整流程。

| 时机 | 内容 | 用途 |
|---|---|---|
| 恢复学习时 | 一个待复习的因果链或新例子 | 确认断点与保留情况 |
| 单元结束 | 少量不看笔记的检查 | 区分听懂与独立应用 |
| 定期复盘 | 重做高影响错题、连接概念 | 处理重复误解 |
| 阶段结束 | 符合目标的任务或模拟考试 | 验证综合迁移 |

### 题源和反馈

- 依目标选题：考试用可核实的公开试题；技术栈用真实代码或获准的隔离练习；理论用明确标注的自编例子。
- 苏格拉底引导逐题等答；只有明确要求整套测验时才批量提供。
- 练习中及时解释错因；独立测验先收答案，再按约定反馈，避免讲解给后续题泄题。
- 报分同时注明是否开卷、是否提示、是否为原题重试；这些成绩不能直接当成无辅助迁移能力。
- 时间限制只在目标需要或用户要求时使用。没有可靠计时就不要声称完成了严格限时测验。

### 是否进入下一单元

遵循已约定的课程标准。没有标准时，以关键因果链和一个新例子的独立解释为依据；80% 可以是协商起点，不能成为所有课程的硬门槛。

关键误解未解决时，重讲最小缺失环节并换例子检查，避免默认整单元重学。用户选择先继续或结束时，保留待复习项并尊重决定；教师自评不能强迫课程继续。跨会话持久保存仍遵守上面的授权范围。
